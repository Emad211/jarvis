# نصب Jarvis روی گوشی تازه

این راهنما برای کسی نوشته شده که فقط یک گوشی اندروید تازه و Termux دارد.
هدف: نصب اپ جارویس + دیمن عاملِ روی گوشی، با یک دستور و یک ویزارد کوتاه.

> **قبل از انتشار این فایل، دو جای خالی را پر کن:**
> `<REPO_URL>` = آدرس واقعی همین مخزن، و مسیر توزیع `jarvis.apk` (بخش ۳).
> هر جای دیگری از مستندات آماده است.

---

## ۰. وضعیت (چه چیزی واقعاً کار می‌کند)

| بخش | وضعیت |
|---|---|
| نصب‌کننده `jarvis-setup` (این مخزن) | نوشته و از نظر ساختاری بررسی شده؛ **روی گوشی تازه اجرا نشده** |
| `jarvisd` روی `127.0.0.1:8780` | روی گوشی مالک کار می‌کند (M1، اکتبر ۲۰۲۶) |
| `gwctl` روی `127.0.0.1:8777` | روی گوشی مالک کار می‌کند (v3) |
| اپ `ir.emad.jarvis` | ساخته و نصب شده روی گوشی مالک |
| ویزارد اول‌بار در اپ | **هنوز پیاده نشده** — مشخصاتش در [`first-run.md`](first-run.md) |

---

## ۱. چه چیزی لازم است

1. **Termux از F‑Droid** — نه نسخهٔ Play Store (قدیمی و رهاشده است و Termux:Boot با آن کار نمی‌کند).
2. **(اختیاری) اپ Termux:Boot از F‑Droid** — برای اینکه دیمن بعد از هر ریبوت خودش بالا بیاید.
   یک‌بار بازش کن؛ پوشهٔ `~/.termux/boot/` را همین اپ می‌سازد.
3. **کلید API یک ارائه‌دهنده** (فقط یکی کافی است):
   - Google AI Studio — <https://aistudio.google.com/apikey> (رایگان؛ برای صدا/میکروفون هم همین کلید لازم است)
   - OpenRouter — <https://openrouter.ai/keys> (مدل‌های `:free` هم دارد)
   - Groq — <https://console.groq.com/keys>
   - AgentRouter — <https://agentrouter.org/console>
4. **Hermes agent روی گوشی** — `jarvisd` بدون آن بالا نمی‌آید
   (مسیر مورد انتظار: `$PREFIX/lib/hermes-agent/app` و venv آن). نصب‌کننده این را
   بررسی می‌کند و اگر نبود، واضح می‌گوید چه چیزی کم است.
5. **(اختیاری) بستهٔ `termux-api`** — برای ابزارهای باتری/کلیپ‌بورد/اعلان. نبودنش هیچ چیزی را خراب نمی‌کند.
6. **فایل `jarvis.apk`** — بخش ۳.

---

## ۲. پنج دستور

در Termux، خط به خط:

```bash
# ۱) ابزارهای پایه
pkg update -y && pkg install -y git python tmux curl

# ۲) گرفتن مخزن
git clone <REPO_URL> ~/hermes-control

# ۳) پیش‌نمایش: همهٔ کارها را چاپ می‌کند و هیچ تغییری نمی‌دهد
sh ~/hermes-control/phone/.local/bin/jarvis-setup --dry-run

# ۴) نصب واقعی (کلید را می‌پرسد؛ کلید روی صفحه چاپ نمی‌شود)
sh ~/hermes-control/phone/.local/bin/jarvis-setup

# ۵) بررسی
sh ~/.local/bin/hermes-svc status jarvis
```

همان پنج دستور به شکل یک خط:

```bash
pkg update -y && pkg install -y git python tmux curl && git clone <REPO_URL> ~/hermes-control && sh ~/hermes-control/phone/.local/bin/jarvis-setup
```

### گزینه‌های نصب‌کننده

| گزینه | کار |
|---|---|
| `--dry-run` | همهٔ کارها را چاپ می‌کند، هیچ تغییری نمی‌دهد و کلید نمی‌پرسد |
| `--key-only` | فقط کلید ارائه‌دهنده را در `~/.hermes/.env` می‌نویسد |
| `--no-boot` | هوک شروع خودکار (Termux:Boot) نوشته نمی‌شود |
| `--port N` | پورت دیمن روی loopback (پیش‌فرض `8780`) |
| `-h` | راهنما |

### چه چیزی ساخته می‌شود

```
~/.hermes/config.yaml      # حداقلی: یک ارائه‌دهنده؛ اگر از قبل باشد دست نمی‌خورد
~/.hermes/.env             # کلید + JARVIS_PORT — مود 600
~/.local/bin/jarvisd.py    # دیمن روی 127.0.0.1:8780
~/.local/bin/gwctl.py      # کنترل روی 127.0.0.1:8777
~/.local/bin/hermes-svc    # سوپروایزر (tmux + حلقهٔ ری‌استارت)
~/.local/bin/jarvis-setup  # خودِ نصب‌کننده (برای --key-only و اجرای دوباره)
~/.termux/boot/start.sh    # اگر پوشه باشد: gwctl + jarvis در هر بوت
~/.hermes/jarvis.log       # لاگ دیمن
```

اجرای دوبارهٔ نصب‌کننده بی‌خطر است: فایل‌های یکسان رد می‌شوند، نسخهٔ قبلی هر اسکریپت
با پسوند `.bak-<تاریخ>` نگه داشته می‌شود، `config.yaml` موجود دست‌نخورده می‌ماند.

**کدهای خروج:** `0` موفق · `1` خطای استفاده · `2` مشکل محیط/پیش‌نیاز · `3` نوشتن کلید یا پیکربندی نشد.

## ۳. اپ را از کجا بگیرم

**الف) ساختن از همین مخزن** (نیاز به ویندوز + ابزارهای build دارد):

```powershell
pwsh -File jarvis\build.ps1
# خروجی: jarvis\dist\jarvis.apk  →  روی گوشی:
adb -s <phone-ip>:5555 install -r jarvis\dist\jarvis.apk
```

**ب) نصب دستی:** `jarvis.apk` را به گوشی منتقل کن (کابل/تلگرام/فایل‌شیر)، از فایل‌منیجر
بازش کن و اجازهٔ «نصب از منبع نامشخص» را برای همان فایل‌منیجر بده.

نکته‌ها:
- بستهٔ اپ `ir.emad.jarvis` است. اپ `hermes-control.apk` (سوپروایزر) برای جارویس **لازم نیست**.
- نسخهٔ v0.1 با کلید دیباگ امضا شده؛ Play Protect ممکن است هشدار بدهد → «Install anyway».

---

## ۴. چه انتظاری داشته باش

- نصب چند دقیقه طول می‌کشد؛ بیشترش برای `pkg install` و بعد گرفتن کلید.
- بعد از نصب، دیمن چند ثانیه وقت می‌خواهد تا «گرم» شود. `/health` زودتر جواب می‌دهد ولی
  `warm: true` یعنی عامل آماده است.
- زمان‌های اندازه‌گیری‌شده روی گوشی مالک (Gemini 3.5 Flash، اکتبر ۲۰۲۶):

  | مسیر | اولین توکن |
  |---|---|
  | دیمن گرم، پیام ساده | ۱.۸ ثانیه |
  | دیمن، پیام واقعی از اپ | ۳.۷–۴.۰ ثانیه |
  | اولین پیام بعد از ری‌استارت (سرد) | ۸–۹ ثانیه |

- Termux باید زنده بماند: اپ جارویس با Termux حرف می‌زند، نه با خودِ گوشی.
  برای همین نصب‌کننده `termux-wake-lock` را در هوک بوت می‌گذارد؛ در تنظیمات اندروید
  هم برای Termux «Battery → Unrestricted» را انتخاب کن.
- اگر آدرس خواست: `http://127.0.0.1:8780` (یا پورتِ `--port`).

## ۵. عیب‌یابی

**«اپ می‌گوید به سرویس وصل نیست»**
```bash
sh ~/.local/bin/hermes-svc status jarvis
curl -s http://127.0.0.1:8780/health     # باید JSON با ok:true برگرداند
tail -n 30 ~/.hermes/jarvis.log
```
اگر `curl` جواب داد ولی اپ نه: آدرس داخل اپ را چک کن و مطمئن شو Termux کشته نشده است.

**«شبکه نیست / مدل جواب نمی‌دهد»**
- Google AI Studio، OpenRouter و Antigravity از ایران بدون VPN جواب نمی‌دهند؛ **AgentRouter** جواب می‌دهد.
- اگر VPN روشن است و اپ به `127.0.0.1` نمی‌رسد، در تنظیمات VPN «split tunneling» را روشن کن و
  `127.0.0.1` را خارج از تونل بگذار (بعضی VPNها ترافیک لوکال را هم می‌بلعند).
- خطای `429` = سهمیهٔ رایگان تمام شده؛ مدل سبک‌تر (`gemini-3.5-flash-lite`) را امتحان کن یا
  در AI Studio صورتحساب را وصل کن.

**«پورت مشغول است»**
```bash
curl -s http://127.0.0.1:8780/health    # چه چیزی آنجاست؟
pgrep -laf jarvisd                      # چند نسخه بالا نیست؟
sh ~/.local/bin/hermes-svc restart jarvis
```
اگر واقعاً پورت در اختیار چیز دیگری است، نصب را با پورت دیگر انجام بده و آدرس اپ را هم عوض کن:
```bash
sh ~/hermes-control/phone/.local/bin/jarvis-setup --port 8781
# در اپ: http://127.0.0.1:8781
```
پورت هم در `~/.hermes/.env` (کلید `JARVIS_PORT`) و هم در هوک بوت ثبت می‌شود.
اگر خودت دستی `hermes-svc start jarvis` بزنی، متغیر `JARVIS_PORT` از محیط tmux خوانده
می‌شود؛ برای همین نصب‌کننده آن را با `tmux setenv -g` هم ثبت می‌کند.

**«Hermes agent نصب نیست» (کد خروج ۲)**
`jarvisd` فقط یک پوسته روی Hermes است. اول Hermes را روی گوشی نصب کن، بعد دوباره:
```bash
sh ~/hermes-control/phone/.local/bin/jarvis-setup
```

**«دیمن بالا نمی‌آید» یا «import شکست خورد» (کد خروج ۲)**

نصب‌کننده آخر کار خودِ `jarvisd` را import می‌کند تا همین‌جا لو برود. اگر خطا داد:

```bash
$PREFIX/lib/hermes-agent/app/venv/bin/python -m pip install fastapi uvicorn httpx pyyaml
ls ~/.local/bin            # باید jarvisd.py، gwctl.py، hermes-svc و (اگر موجود است) jarvis_fast.py را ببینی
sh ~/.local/bin/hermes-svc restart jarvis
```

**«tmux نیست»**
```bash
pkg install tmux
```

**«Termux:Boot کار نمی‌کند»**
- پوشهٔ `~/.termux/boot/` را فقط اپ Termux:Boot می‌سازد؛ اول اپ را باز کن، بعد نصب‌کننده را دوباره بزن.
- هوک را چک کن: `cat ~/.termux/boot/start.sh`
- در تنظیمات اندروید، Termux را از بهینه‌سازی باتری خارج کن.
- نصب‌کننده هرگز `start.sh` متعلق به اسکریپت دیگری را پاک نمی‌کند؛ در آن حالت هوک را در
  `~/.termux/boot/jarvis.sh` می‌نویسد (Termux:Boot همهٔ `*.sh` آن پوشه را اجرا می‌کند).

**«کلید را عوض کردم ولی همان خطا»**
عامل گرم، کلید را در حافظه نگه می‌دارد:
```bash
sh ~/.local/bin/hermes-svc restart jarvis
```

## ۶. امنیت (مهم)

- `jarvisd` **فقط** روی `127.0.0.1:8780` و `gwctl` **فقط** روی `127.0.0.1:8777` گوش می‌دهند.
  هیچ چیزی روی LAN یا اینترنت باز نیست.
- **در نسخهٔ v0.1 هیچ احراز هویتی نیست** (همان مدل اعتماد gwctl). یعنی هر اپی که روی
  همین گوشی نصب شود می‌تواند به دیمن وصل شود، پیام بفرستد و ابزارها را اجرا کند.
  اگر این برایت مهم است: گوشی را در اختیار دیگران نگذار و روی گوشی اپ ناشناخته نصب نکن.
- **هرگز** این دو پورت را با `ssh -R`، `adb forward`، تونل یا port-forward به بیرون باز نکن.
  برای دسترسی از راه دور، نسخهٔ M5 (تونل خصوصی + توکن) برنامه‌ریزی شده است.
- کلیدها فقط در `~/.hermes/.env` با مود `600` هستند و در `config.yaml` نوشته نمی‌شوند.
  نصب‌کننده کلید را چاپ نمی‌کند و آن را به‌عنوان آرگومان به هیچ برنامه‌ای نمی‌دهد
  (آرگومان‌ها در `ps` دیده می‌شوند).
- `~/.termux/termux.properties` را با `allow-external-apps=true` **فقط** اگر از دکمهٔ
  بیدارباش اپ Hermes Control استفاده می‌کنی باز کن؛ آن تنظیم اجازهٔ اجرای دستور در Termux
  را به اپ‌های دیگر می‌دهد و یک حفرهٔ واقعی است. جارویس به آن نیاز ندارد.
- لاگ‌ها (`~/.hermes/jarvis.log`) ممکن است دستورها و مسیرها را داشته باشند؛ قبل از اشتراک
  نگاهشان کن. کلیدها در لاگ نمی‌آیند ولی فرض نکن بقیه چیزها هم بی‌خطرند.

